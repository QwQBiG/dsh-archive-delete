# 操作与恢复

简体中文 · [English](operations.md)

## 状态

| 状态 | 位置 | 后续操作 |
| --- | --- | --- |
| 已归档 | 宿主原始日志 | 预览并移动 |
| 待重启处理 | 原始日志及排队请求 | 重新核对、取消或等待启动 |
| 回收站 | 插件回收站及恢复元数据 | 恢复或永久清除 |
| 失败／跳过 | 逐项结果中显示 | 查看原因并重试目标 |
| 已永久清除 | 所选日志和恢复元数据已移除 | 完成 |

批量结果分别显示成功、待处理、跳过和失败的目标数。损坏记录单独提示，健康记录仍留在列表中。

刷新时会用同一请求回执更新已显示的结果，包括另一窗口取消或启动处理后的状态。其他请求不会替换本地结果。

## 确认

预览将所选 ID 展开为母会话／子代理组，显示成员、大小和到期时间，以及可处理、尝试闲置释放和受保护的目标数，有效期五分钟。内容、登记或关系变化后，需要重新预览。

每个预览授权一个请求。服务在将请求意图写入持久记录前，就将预览标为已使用；即使写入报错，预览也保持已使用状态。通过同一请求 ID 重试，可以恢复已有意图和结果。维护期间，客户端清空活动预览，并忽略之后才返回的预览响应。

请求可能已经记录后发生的错误，会保留“结果尚未确认”状态。选择“重试同一次请求”；重试遇到临时拒绝时，原请求仍可继续查询。服务确认回执和关联操作均不存在后，才返回预览核对流程。

## 移动与待处理请求

1. 检查归档组及其活动状态。
2. 如果 DSH 持有闲置的写入器，通过原生生命周期释放，再次检查会话组。
3. 取得成员写锁，持久化请求和操作元数据。
4. 经暂存位置移动成员目录，更新原生登记并提交回收站条目。
5. 持久化每项结果，移除已完成的操作日志。

写入器仍被持有时，请求保持待处理。选择 **取消等待并重新核对**，会取消排队请求并打开新预览；取消或关闭这个预览时，原始日志仍在原处。启动时，插件先恢复中断的操作和取消请求，再对剩余的排队移动检查一次。内容变化或会话取消归档后，旧请求结束，需要重新确认。

取消请求会记录对应的排队操作 ID。发生中断后，启动恢复会完成这些操作的取消；同一会话后来重新确认的请求单独处理。旧版取消记录可能没有这些 ID，此时相关排队移动会保持暂停，直到你再次确认取消。其他排队会话仍可继续处理。

## 恢复与永久清除

恢复后，会话组回到原工作区并保持已归档；工作区缺失时归入未分组。目标位置已经存在时，该项报告冲突。

日志位于回收站或暂存区期间，如果原来的内部空分桶已被移除，恢复或回滚会在已有会话存储根目录下补建分桶，不重建项目文件夹。

永久清除在当前进程中处理所选回收站条目，移除日志和恢复元数据，无法撤销。清除中途停止时，结果会说明剩余状态，供你核对后重试。只有剩余会话组完整时，才能恢复。

## 最近永久删除

在回收站展开 **最近永久删除**，可查看近 30 天内最多 200 条记录，包括会话 ID、确认完成时间、原始日志大小和成员数。归档操作不可用时，仍可查看已有历史。持有存储写锁的实例会在读写历史时清理过期记录。

历史写入中断可能造成记录缺失。如果删除在启动恢复时才得到确认，记录显示的是恢复确认时间。

## 操作日志恢复

| 记录阶段 | 启动处理 |
| --- | --- |
| `moving` / `detached` / `trashed` | 核对已提交的回收站条目，或将暂存数据回滚到原位置 |
| `restoring` | 将未完成恢复回滚至回收站 |
| `restored-metadata` / `restored` | 完成宿主登记和回收站清理 |
| `purging` / `purged` | 完成空条目清理；若有剩余文件，报告后等待明确重试 |
| `pending` | 复查原组并尝试一次排队移动 |

恢复时，将实际路径和写锁与已记录的归属核对。对于已有清理记录，原始空 bucket 缺失可以接受；数据冲突或无法读取时会显示诊断。报告问题时，请一起保留受影响的条目及对应操作日志。

完成的请求回执保留 ID 和结果，供重放使用。列表每次重新读取所展示的内容，排序最多缓存一分钟，到期后的第一次读取会重建排序。启动时也会清理临时回执文件。

## 存储观察

存储扫描可以独立取消。结果包含观察时间、完整或部分完成的状态、分类和文件类型合计，以及跳过项。重新扫描同一范围时，保留上次结果直到新结果返回；切换范围时清空。取消扫描后，其他操作照常运行。

## 更新恢复

| 状态 | 操作 |
| --- | --- |
| `installing` | 等待原生管理器，插件会继续检查状态 |
| `installed` | 目标已安装，提示时完整重启以加载更新 |
| `restart-required` | 完整退出并重新打开 DSH |
| `failed` | 查看诊断并核对已安装版本，再重新核对一次升级 |
| `interrupted` | 重新检查发行版和当前安装 |
| `unknown` | 核对安装状态或重新核对此次请求，仍不明确时完整重启 |

检查和安装日志按 profile 分别保存在 `updates/`，已校验安装包位于 `updates/packages/`。重新核对同一请求时，读取原生安装状态，已记录的管理器调用不重复执行。轮询间隔从 3 秒延长至 15 秒、60 秒。

替换安装包前，插件先完成排队的归档操作，并暂停新变更。卸载时取消尚未交出的校验；原生管理器接受安装后，后续工作由它负责。启动时，插件会将保存的目标与已安装、已加载版本进行核对。

每次确认安装都有独立回执，后续尝试和重启会保留这些记录。重新核对旧请求会返回它已记录的结果；较新的安装正在执行或结果尚未明确时，归档变更仍保持暂停。旧版只记录最近一次安装的格式会在启动时迁移。
