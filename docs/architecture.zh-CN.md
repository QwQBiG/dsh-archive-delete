# 架构

简体中文 · [English](architecture.md)

目标环境为 macOS 和 Windows 上的 DSH Desktop `0.2.1-rc.3` / `0.2.1-rc.5`、JSONL 持久化。React、原生控件、会话持久化、工作区登记及活动／写锁服务由 DSH 提供。

## 模块

| 模块 | 职责 |
| --- | --- |
| `client` | 原生入口、选择、预览、确认及结果 |
| `service` | 会话组校验、串行转换、请求与恢复 |
| `dsh-adapter` | 宿主准入、关系、活动、写锁及原生登记 |
| `storage` | 回收站清单、操作日志、移动、恢复及永久清除 |
| `storage-inspector` / `storage-usage` | 来源解析和有上限的元数据扫描 |
| `update-source` / `update-service` / `update-host` | GitHub 校验、更新状态和原生 profile 安装 |

宿主内部结构集中在适配层。兼容性变化同时更新该边界及其原生集成测试。

## API 与客户端状态

所有者鉴权的 `/api/dsh-archive-delete` 路由接收 JSON 流，请求体上限为 64 KiB。

| 动作 | 输入 | 结果 |
| --- | --- | --- |
| `list` | — | 支持状态、归档、回收站、最近结果、诊断及工作区选项 |
| `preview` | 动作和目标 ID | 组成员、大小、处理状态及到期时间 |
| `execute` | 预览 ID、请求 ID | 逐项结果及计数 |
| `cancelPending` | 会话 ID、请求 ID | 取消结果 |
| `storage` | 可选工作区 ID | 存储观察结果 |
| `updates` | 强制检查标记 | 发行及安装状态 |
| `installUpdate` | 候选 ID、请求 ID | 安装状态 |

服务端解析路径和发行资产。客户端校验响应字段，跟踪请求代次，通过同一请求 ID 核对不明确的变更响应。页签／分页／排序变化清空选择，维护状态作废在途预览。确认到期状态与可处理／尝试闲置释放／受保护数量来自当前预览。

## 数据与转换

数据区域初始化前取得存储写锁。状态位于 `<DSH_HOME>/archive-delete/`：

| 路径 | 内容 |
| --- | --- |
| `trash/<entry>/` | 清单及按成员编号的日志目录 |
| `staging/<entry>/` | 移动中的会话组 |
| `operations/` | 持久转换阶段和恢复数据 |
| `receipts/` | 请求进度与幂等结果 |
| `updates/` | 按 profile 隔离的检查／安装日志 |
| `updates/packages/` | profile 依赖引用的已校验安装包 |

会话组包含母会话和明确的专属子代理。fork 也有母会话指针，因此根据宿主关系元数据判断所有权。列表每次建立一次关系索引；损坏身份产生诊断，已知关联组受保护，祖先无法定位时阻止归档移动。

转换串行执行，重叠刷新共用一次列表任务。预览在持久化请求准入前消费，原请求 ID 可恢复意图／结果。请求意图先于文件变更持久化，每项结果落盘后才结束对应的终态操作记录。

移动在同卷进行并保留原始日志字节，适配层在文件转换后处理工作区／投影登记。恢复使用原归档状态和工作区，原登记缺失时归入未分组。确认后的永久清除移除所选回收站日志及恢复元数据。

日志移动前同步暂存父目录项；永久清除依次同步成员文件删除、成员目录移除和清单移除，再同步回收站父目录与终态日志。POSIX 使用目录 fsync，Windows 提供进程中断恢复，整机断电持久性不作保证。按路径删除前再次核对所属目录身份。

完成回执保留标识和结果，移除标题。最近结果使用十条完成记录的内存索引，并校验实际展示的回执；初次清点和启动恢复随历史数量增长。临时文件在启动时显式清理。

## 原生生命周期与写锁

已确认的手动移动可通过原生 AgentLoop 生命周期释放完全闲置的宿主受管组。准入检查归属、输入、维护、活动任务及子项，随后服务重新检查成员／内容并取得正常写锁，再移动。待处理请求在启动时尝试一次，手动重新核对提供新的即时释放尝试。

会话头比较将宿主省略的 `delegationDepth` 归一为磁盘默认值 `0`，其他值和会话身份继续参与复查。

macOS 使用宿主 flock 句柄；Windows 使用宿主 JSONL 信号量名称，同时保留原路径及迁移后路径。规范本地路径使锁身份一致。插件存储写锁覆盖该进程的恢复及转换所有权。

## 存储观察

适配层解析配置的 DSH 位置和已登记工作区。DSH 扫描排除项目目录及单独分类的子目录；工作区扫描结束后复查所选登记／路径，并比较排除集合。

扫描器通过有上限的目录遍历读取元数据：50,000 个条目、32 层深度，inspector 预算为 5 秒。批次间让出执行，支持取消，记录跳过／变化／不可用项，结果携带观察时间和完整／部分状态。

主合计按规范路径及已核实文件身份去重。分类可能重叠，目录合计按文件路径计数。文件类型按目录组成和扩展名规则划分为依赖、构建目录、版本控制数据、日志、媒体、压缩包、代码／配置、文档及其他文件；类型小计在分类内部去重，每个大文件带有类型。

存储界面显示紧凑分类摘要，按需展开文件类型、大文件和目录。同范围重新扫描时保留带时间的上次观察，切换范围则清空。

## GitHub 更新

来源读取 `QwQBiG/dsh-archive-delete` 的更高稳定发行版，最多考察 20 条发行及五个新版候选，要求精确 DSH／平台声明。发行检查缓存 24 小时，手动检查至少间隔一分钟；失败至少等待一小时，并遵守 GitHub 退避。

服务端 pin 绑定发行／资产身份、版本、大小及 SHA-256。来源操作共用 15 秒网络预算，安装前校验总预算为 30 秒。包校验器限制压缩／展开大小和 tar 条目，检查路径及包清单，要求预编译产物。SHA-256 核对来自 TLS／GitHub 仓库来源的内容一致性。

确认后的安装包保留在 `updates/packages/`，DSH 管理器在当前 profile 替换同一 bundle。检查和安装日志按规范 profile 目录的哈希隔离。替换前归档队列排空，安装任务位于队列之外，使自卸载可以完成。

实例卸载取消发现／安装前校验，已委托的原生安装保持自身生命周期。同请求重新检查原生安装状态，已记录的安装不重放；观察间隔从 3 秒退避到 15 秒、60 秒。正在运行和已安装版本决定启用／重启状态。

安装包通过 `engines.dsh` 声明支持的宿主：`0.2.1-rc.3 || 0.2.1-rc.5`。包准入接受有数量上限的精确版本列表。发行元数据提供默认的 rc.3 资产及对应 rc.5 的资产，共用同一个安装包和校验值。ASAR 宿主清单由专用读取器核对所属归档后读取。

## 安装包与诊断

Release `.tgz` 包含 `files` 白名单及编译后的 `lib/`。产物脚本调用运行时包准入，检查脚本在执行发现／下载样本前核对 `.tgz.sha256`、`.update.json` 和实际字节。

启动完成恢复及 API 注册后，记录版本、宿主和回收站路径；打包的 Doctor 提供离线登记、文件和访问检查。使用方式见 [安装命令](installation.zh-CN.md)、[状态恢复](operations.zh-CN.md) 和 [验证记录](acceptance.zh-CN.md)。
