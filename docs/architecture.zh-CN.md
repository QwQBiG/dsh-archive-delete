# 架构

简体中文 · [English](architecture.md)

## 目标与边界

数据变更生命周期保持为：**已归档 → 回收站 → 恢复为已归档，或显式永久清除**。目标为官方 DSH Desktop `0.2.1-rc.3` 与 JSONL 持久化后端。支持 macOS 和 Windows，两平台均已执行原生宿主与包生命周期检查。

实时会话、工作区、活动状态和会话历史以 DSH 为准；原始日志字节是会话内容的事实来源。插件拥有操作记录、回收站清单、更新记录／安装包和原生界面贡献，同时提供有限的只读查看，用于宿主配置的存储和用户手动选择的已登记工作区。经确认的 GitHub 更新由当前 profile 的 DSH 原生管理器安装；不替换工作区注册表、会话后端、投影缓存、侧边栏或包管理器。

## 四个模块

| 边界 | 职责 | 禁止承担的职责 |
| --- | --- | --- |
| `client` | 原生菜单、管理弹窗、选择、预览、确认与本地化结果 | 接受磁盘路径、猜测移动成功或直接修改存储 |
| `service` | 校验动作、检查完整会话组、串行转换、执行前复查、报告部分结果 | 耦合未公开的宿主字段，或无日志地修改文件系统 |
| `dsh-adapter` | 精确版本准入、列表与活动查询、专属子代理关系、规范路径、兼容写锁、原生闲置释放准入、登记移除与恢复、可信存储来源解析 | 仅凭传入路径判断所有权，或默默接受未知宿主版本 |
| `storage` | 插件清单、持久阶段记录、同卷移动、恢复、受限永久清除及独立的只读元数据扫描器 | 递归删除任意路径、覆盖冲突源目录或清理共享附件 |

共享类型集中在契约模块。服务依赖适配接口，不导入整套 DSH 运行时。因此可以用合成适配器测试真实存储转换，再由独立集成测试验证宿主边界。

更新使用独立的来源、服务、宿主适配与客户端契约：`update-source` 发现和校验固定 GitHub 发行资产，`update-service` 管理检查缓存与安装意图，`update-host` 对当前原生管理器／profile 执行准入，更新客户端呈现状态与确认。这些组件不混入会话恢复回执，也不替代宿主安装机制。

## 界面与传输

在已归档会话的原生行菜单加入 **移入回收站**；插件详情增加 **管理归档、回收站与存储**，打开已归档／回收站／存储概览原生弹窗。使用 DSH 组件与模块加载机制，React 和 DSH 由宿主提供。

浏览器经 DSH 已鉴权连接网关调用 `/api/dsh-archive-delete`，请求范围保持精简：

- `list`：支持状态、归档记录、回收站记录、受保护记录诊断、最近操作结果，以及已登记工作区的 ID／标题。
- `preview`：操作类型（`trash`、`restore`、`purge`）及选中 ID。
- `execute`：不透明的预览 ID 和请求 ID。
- `cancelPending`：选中会话 ID 和请求 ID。
- `storage`：不带工作区 ID 时查看配置的 DSH 存储，或带一个当前已登记的工作区 ID；不接受客户端指定路径或扫描上限。
- `updates`：通过 `force` 布尔值请求缓存状态，或受频率限制的手动检查。
- `installUpdate`：用户查看更新并显式确认后，提交服务端签发的候选 ID 和请求 ID。

浏览器不传入源路径或目标路径。预览包含目标、组成员、大小及可执行／待处理／阻止状态。执行时服务再次检查权威状态；预览并不授权操作已经变化的数据。

结果区分 `moved`、`pending`、`restored`、`purged`、`cancelled`、`skipped`、`failed`；批量计数由逐项结果生成。排队不等于已经移入回收站。

更新卡片显示正在运行／已安装版本、上次检查时间及发行状态。更新说明为长度受限的纯文本，由渲染器转义，不作为可执行 HTML 渲染。浏览器不传入更新 URL、校验和、归档字节、安装包路径、包名、profile 路径或命令，只提交候选／请求标识。响应结果不明时保留同一请求 ID，用于核对状态或重试，不能据此授权第二次升级。

仅限所有者的鉴权路由以流式读取请求体，在继续累积输入前执行 64 KiB 上限。请求与响应边界校验枚举及可选文本字段。确认页计算可处理／尝试闲置释放／受保护数量，更新到期状态，永久清除使用独立确认样式。维护会作废待返回的预览代次，较晚响应不能重新打开旧确认。时间使用宿主当前翻译语言。

归档列表每次清点只建立一次母子关系索引。身份损坏或重复会产生独立诊断，健康行继续显示；已知关系组整体保护，祖先无法定位时禁止归档变更。回收站同样隔离无法读取的条目，不删除数据或编造恢复元数据，并复用一次操作清点。闲置释放能力诊断按原因去重，不记录会话内容；原生依赖解析 Promise 失败后会重置，允许后续重试。

## 持久化与宿主一致性

插件状态放在 `<DSH_HOME>/archive-delete/`：转换日志在 `operations/`，移动中的暂存内容在 `staging/`，物理回收站在 `trash/`，请求进度与回执在 `receipts/`。实际 home 由正在运行的宿主提供。回收站必须在会话根目录之外，并处于同一磁盘卷。创建数据区域前先取得插件存储写锁，竞争失败的进程不初始化这些区域。

一个会话组包含选中的母会话，以及明确属于它的专属子代理子孙。只有 `parentSession` 不足以证明子代理所有权，因为独立 fork 也有母会话关系。关系未知或冲突时，在任何移动前阻止整组操作。

移动文件与修改 DSH 登记属于多步操作，不是跨系统原子事务。变更前先持久化请求意图，再逐项目标写入结果；关联的操作记录保存执行进度及原登记信息，用于协调失败或中断后的状态。完成证明会保留到请求结果持久化，弥合文件提交与浏览器响应之间的空隙。移动前校验并锁住组成员；通过适配层的宿主串行写入路径更新已知登记，不直接改写 `workspace.json`。

插件不维护第二份全文或投影镜像。恢复所需元数据仅在仍可恢复时保留，并随回收站条目永久清除。不额外复制用户首条消息以补侧栏标题。独立的幂等回执保留请求／目标标识及操作结果，移除会话标题；这些回执不是会话备份。

恢复 JSON 的读写上限同为 8 MiB。初始请求意图限于 6 MiB，在任何转换开始前，为最多 100 项有长度边界的结果预留空间。元数据过大时，在写入／移动前拒绝并要求缩小批次；已准入的意图必须能在结果累积时继续写入。

预览在首次发布持久请求意图前即被消费，发布结果不明也不能换 ID 复用；同请求恢复仍可读取已有意图／结果。重叠刷新共用一个列表 Promise，列表与变更继续串行，保证观察一致。完成回执保留供精确幂等重放；最近结果的内存索引校验最多十条实际展示的完成回执，避免每次刷新解析全部历史。初次目录清点和启动恢复仍随历史数量增长。临时回执清理是显式启动步骤，不再混入只读回执列表。

日志移入新暂存目录前，先在父目录中同步该目录项。POSIX 永久清除依次同步成员文件删除、成员目录移除和清单移除，再移除条目、同步回收站父目录，并完成持久操作。已知的原始空 bucket 缺失只在有记录的恢复／清理中放行，已有不安全路径仍会拒绝。按路径删除前立即复核目录身份，但 Node 没有可移植的 `unlinkat`，同用户攻击者在最终系统调用中替换父目录仍不在保证范围内。

## 只读存储查看

适配层从正在运行且版本精确匹配的宿主解析存储来源：JSONL 持久化、附件与附件缓存根目录、spill 根目录、JSON 设置后端根目录、配置的搜索索引文件，以及 DSH 数据目录中的插件状态、缓存、profile 和其他宿主数据。不会假定全部位置都在 DSH home 内，也不初始化缺失服务。SQLite 来源只测量配置的普通文件，不扫描它的父目录。DSH 扫描还排除有效的已登记项目路径，包括 DSH home 内的项目；读取这些文件需要另行明确选择工作区扫描。解析排除项只枚举注册表元数据。已知子根目录从父目录排除；其余重叠及已核实的重复身份仍明确报告，并在全局去重。

工作区枚举只读注册表。扫描重新解析单个已登记 ID，拒绝磁盘根目录、用户目录及其祖先、不安全重定向和受保护宿主存储内部位置，并排除合规项目内部已知的宿主数据子目录。扫描结束后重新读取成员资格与路径，过期登记不能悄悄改变目标。服务端路径不越过鉴权 API 边界；列出工作区和打开界面不会遍历项目目录。

storage-usage 扫描器流式读取目录条目，仅使用 lstat／realpath 元数据，不读文件内容，不运行 Git 或项目程序。默认上限为 50,000 个条目、32 层目录和 3,000 ms；inspector 使用固定 5,000 ms 扫描预算，条目和深度上限相同。时间预算限制可协作中断的扫描工作，不能中断已经等待中的操作系统调用。扫描器在有限批次之间让出执行、接受取消、关闭目录句柄，不遍历符号链接、junction、重定向祖先、跨卷子项或特殊文件。前后身份检查及最后一轮元数据复查会报告变化，不把观察时段描述为原子快照。权限失败、根目录缺失、服务不可用、身份未知及条目／时间／深度上限均明确保留；未测量分类使用 null 字节，不显示为零。

主合计为普通文件的逻辑字节，跨分类按规范路径及已核实的 dev + ino 身份去重。分类内部各自去重；目录合计按文件路径累计，包含硬链接别名。重叠与未知身份会报告，因此这些小计不能直接相加，任何数值都不代表独占物理占用或可释放空间。大文件记录使用相对路径及 source: unknown，不推断 AI 来源或可清理性。

StorageInspector 独立于服务变更队列，管理一次活动扫描及其取消生命周期。客户端在范围／页签／窗口变化时取消并忽略过期响应；扫描不能执行、确认或核对解决数据变更。刷新工作区列表只更新可选项，新的大小测量需点击扫描按钮；已知扫描／工作区拒绝代码提供本地化后续指引。同范围重新扫描会保留带时间的旧结果并明确标注，取消／失败后也保留；切换范围会清空。含义相同的排除集合不依赖枚举顺序比较。结果只保存在客户端状态，不增加扫描数据库、自动清扫或新的清理权限，也不自动回收已有幂等回执。

## 当前回收站大小

TrashStore.entrySnapshot 在同次校验观察中计算当前剩余普通文件字节及确认指纹，校验清单、允许的成员／文件名称及身份；确认 token 忽略可变锁文件，返回前重新检查测得条目。存在对应日志的部分永久清除可以缺少成员／日志；没有操作日志证明的缺失数据会被拒绝。列表与恢复／清除预览使用当前观察，不沿用原成员保存的大小。仍存在的所属迁移临时文件计入条目当前字节，恢复元数据和锁文件不计，因此可能不同于整个分类的存储扫描。

服务仍在取得原生写锁后、恢复或永久清除前比较已确认指纹；大小或身份变化会使旧确认失效。测量存储不会扩大删除权限，也不承诺已释放的物理字节。

## 确认后的闲置释放

只有新的手动移动执行可以要求适配层释放已加载的归档组。固定版本适配层通过 Cordis effect 元数据及精确原生身份定位宿主拥有且有序的 AgentLoop 生命周期清理函数，不自行删除注册表条目或关闭归属不明的写入器。这是所准入宿主代际的内部能力，不是稳定的跨版本卸载 API。准入要求生命周期可明确识别、所有受影响成员完全闲置、收件箱无待处理输入、没有维护活动，且运行时拥有的子项全部在已确认的专属组内。能力缺失或不明确时保留待处理回退；活动工作和外部写占用仍受保护。

内存与持久化会话头按固定 JSONL 格式比较：省略的 `delegationDepth` 与磁盘默认值 `0` 等同，字段顺序不影响结果。其他字段、显式无效值及会话对象身份仍严格核对；这不会放宽清理前后的源文件指纹检查。

原生清理完成后，服务重新检查归档状态、成员及内容指纹，并在移动任何文件前取得正常会话写锁。指纹变化要求重新确认。打开列表／预览和启动时重放旧队列，都不会触发此闲置释放路径。

已有待处理行通过现有取消 API 结束旧请求，再请求新预览。较晚返回的取消响应不能重新打开已关闭弹窗；取消结果不明时，必须先核对结果再发起新操作。新预览仍需确认；浏览器边界没有获得新的文件系统权限。

## 平台存储与写锁

- macOS 对每个 `session.lock` 使用正在运行的宿主提供的原生 flock；同卷重命名后，已持有句柄仍保留所有权。
- Windows 通过 JSONL 后端现有、由宿主提供的原生绑定，使用同样的内核命名信号量约定，名称来自解析并统一大小写的路径。转换同时保留原会话路径和当前暂存／回收站路径的锁，避免日志迁移绕过占用检查；恢复时也先锁住尚不存在的原目标。插件存储同样使用兼容平台的写锁边界。
- Windows 只接受经过本地驱动器类型检查的本地驱动器绝对路径，拒绝 UNC／网络路径、设备命名空间、保留名称、含混别名及符号链接／junction 重定向。配置根与会话目录必须与规范位置一致，仅允许大小写差异；短名称别名或 junction 祖先目录不能产生另一套写锁身份。再次核对规范根与成员路径；相邻目录前缀和大小写别名不会授予访问范围。
- 恢复 JSON 必须是大小受限的普通文件，解析前核对文件身份。在语义有效的平台执行 POSIX 所有者／权限检查；Windows 不把 POSIX 权限位当作 ACL 保证，沿用已有 DSH home 的访问控制。
- 元数据文件在原子替换前执行刷盘；POSIX 还同步所在目录。Windows 依靠可恢复操作记录协调，因为 Node 无法提供同样的目录同步操作。进程中断恢复与断电持久性分别对待，不承诺断电保证。

## 兼容策略

首版使用精确版本门禁，不承诺全部 `0.2.x` 都兼容。版本来自当前 profile 的运行时安装锚点，不以插件固定的 peer 包版本冒充真实宿主。数据变更要求宿主版本与平台匹配、使用 JSONL 后端、规范路径安全，且活动／写锁／登记能力齐全。无法确认时返回明确的不支持或阻止结果。版本不匹配会在启动诊断中说明所需／当前版本和升级方式，并保留可读的禁用管理弹窗。`engines.dsh` 描述兼容范围，不是安装期门禁。

Cordis、app boot、home paths、原生系统绑定和 React 由宿主提供，其 peer 声明在包管理元数据中标为可选，避免误导性的缺失警告；运行准入仍检查实际能力。插件不添加安装钩子。DSH 原生管理器会注册 bundle。CLI 用户安装后核对 `dsh.profile.bundles`，只在缺失时添加包名；经过管理器的启动器可自动协调，仅安装依赖的调用模式则需显式补登记。

所有宿主内部结构访问集中于适配层。后续宿主变化需要明确更新适配并提供实测证据，不能只放宽版本范围。

## GitHub 发现与安装包校验

更新来源固定为 `QwQBiG/dsh-archive-delete` 的 GitHub Releases，tag 必须为稳定的 `vX.Y.Z`。最多考察 20 条发行记录，按版本降序检查最多五个更新稳定语义版本的元数据，排除草稿、预发布与降级。候选必须具有发行版中对应的 `.update.json` 资产，`requiredDshVersion` 与宿主精确相等，并支持当前 macOS／Windows 平台。自动发现只下载元数据，不下载 `.tgz`。

生产 HTTP 上限为：发行响应 1 MiB、更新元数据 32 KiB、每个来源操作共用 15 秒预算（包括发现时的列表／元数据请求）、最多三次重定向。安装前校验的各来源阶段另有合计 30 秒总预算。GitHub `Retry-After` 秒数／HTTP 日期及限流重置时间会设置有上限的退避，手动检查也不能绕过。网络取决于启动时的运行环境；插件不设置全局代理／agent，也不自动启用 `HTTPS_PROXY`。初始 API 与下载 URL 固定在本仓库／tag／资产下；拒绝 API 重定向，资产重定向只允许准入的 HTTPS GitHub 下载／CDN 主机，URL 不得带凭据。网络、超时、限流、元数据格式与重定向错误均明确保留，不显示为当前版本已最新。

服务端 pin 绑定发行版与资产身份、元数据身份、版本、字节数、宿主／平台声明及 SHA-256；浏览器仅收到公开候选信息。确认后重新检查并重新获取元数据校验，再下载安装包；pin 变化不能沿用旧确认。下载字节必须与声明长度及 SHA-256 一致。SHA-256 证明与选定发行内容一致，信任仍来自 TLS 和 GitHub 仓库，不是独立的发布者签名或代码审计。

在内存中解压并解析归档，不解包到磁盘，也不执行内容：压缩包最多 16 MiB、展开最多 64 MiB、tar 条目最多 4,096 个。拒绝不安全路径、链接、重复／大小写冲突条目、特殊条目，以及错误的头部／校验和。包清单最多 64 KiB，必须与包名、已确认版本、精确 DSH 要求、bundle patch 及预编译宿主／浏览器产物匹配。拒绝安装／prepare 钩子、运行依赖、可选依赖及打包内置依赖。Peer 仅允许五个已知、由宿主提供且标为可选的包，保持宿主 Cordis／React 实例复用。

## 更新准入、持久化与启用

只有在受支持的 DSH Desktop `0.2.1-rc.3` 完成归档初始化与鉴权路由注册，且原生管理器确认本包是当前 profile 中唯一明确的自有安装，才启动更新器。不会更新内置、共享或其他 profile 的安装。缺少该能力时，已准入的归档功能仍可用，不启动更新器；未来宿主不受支持时仍显示原有禁用界面／版本门禁，不能承诺通过更新器自行越过门禁升级。

服务端对规范 profile 目录（`UpdateHost.profileId`）计算 SHA-256，按 profile 隔离更新状态。`updates/<profile-hash>.check.json` 将发现缓存与会话状态分开。成功／最新／不兼容的观察缓存 24 小时，自动检查失败后至少隔一小时重试，并遵守 GitHub 要求的更长限流等待；手动检查可在至少间隔 60 秒后绕过常规缓存，但不能绕过保留的限流窗口。服务端每小时唤醒和客户端状态轮询共用该缓存，不会每次都请求 GitHub。发现失败可保留旧候选供参考，但观察状态必须为错误；安装仍需重新验证为可用的 pin。

只有明确确认后才下载安装包。已校验字节原子保存在私有位置 `<DSH_HOME>/archive-delete/updates/packages/<version>-<sha256>.tgz`，原生安装前再次校验。管理器将这份精确本地归档作为当前 profile 的同名 bundle 安装，并在 profile 元数据／锁文件中保留 `file:` 来源。为可复现重装，安装包文件必须保留，不自动清理仍被引用的归档。继续通过 GitHub 分发，不发布 npm，也不自建包运行器。

校验完成后，归档服务等待已准入操作排空，在调用管理器前关闭变更入口。安装本身不放入归档队列，因为原生管理器在热替换时可能等待本插件实例卸载。`updates/<profile-hash>.installation.json` 独立持久化该 profile 的请求、候选、目标版本和结果；保留的安装包字节可以共享，但安装结果不能混用。并发确认不能启动两次管理器操作，相同请求 ID 会为该操作重新读取原生安装状态，不重放已记录的管理器调用。匹配的已安装目标可核对为已安装／待重启；仅发现旧版或无法读取目标，不足以证明委托任务已结束。客户端观察间隔从 3 秒退避到 15 秒、60 秒，直到明确或销毁；安装进行中、结果不明或等待重启时，阻止新升级。

插件实例卸载会取消并等待发现检查，取消安装前校验，但不取消或等待已经交给原生管理器的安装，否则自替换可能死锁。分别报告正在运行与磁盘已安装版本；启动时根据实际安装包和已加载代码核对安装记录。已安装版本变化、等待重启或结果不明时继续保护归档变更；用户可能需要完整退出并重新打开 DSH。不承诺升级无需重启。

原生集成验证同 profile 替换、安装包保留，以及包被拒绝后的清单／锁文件恢复。任意启用或热重载失败可能发生在安装状态改变之后，不能保证完整自动回滚。结果不明时保留可见状态，用状态检查或同请求处理，并给出诊断与重启指引，不隐式发起第二次安装。会话、回收站及会话恢复记录不属于更新操作范围。

发行生成在写入校验／更新资产前执行与运行时相同的受限包准入。发行检查断言公开 `.sha256`、`.update.json` 的摘要／字节数与实际安装包一致，再通过本地响应样本执行发行发现、pin 复核及下载准入。

## 分发与诊断

主要安装来源为按包文件白名单构建的固定版本 GitHub Release `.tgz`，并提供对应 `.tgz.sha256` 与 `.update.json` 资产。更新卡片可发现兼容发行版，经确认后通过原生管理器升级；明确添加新发行版 URL 仍是手动升级方式。插件不增加 postinstall 注册钩子，也不直接编辑 profile。仅安装依赖的 CLI 路径需要核对清单注册；卸载后若宿主留下残留条目，只清理本插件的精确 bundle 条目。

成功启动仅在恢复和鉴权 API 注册完成后，报告插件版本、所需／当前宿主版本及解析出的回收站目录。禁用或启动失败时保留相应诊断，不输出虚假的加载成功日志。该信号属于当前进程；旧目录和配置导出不足以证明当前已启用。

单独打包的 Doctor 是离线只读诊断边界，检查所选 profile／包元数据、宿主包版本及既有存储的访问权限，不打开会话日志，不创建目录、不修改 bundle，也不执行修复。离线通过只说明前置检查结果；实际启用由实时管理 API 和本次加载日志证明。

## 范围决策

- 不自动过期清空回收站，不创建后台清理定时器或 Agent 删除工具。
- 不强制中断活动或非托管会话，不抢占写锁；释放完全闲置的托管生命周期需要新的手动确认。
- 不做附件垃圾回收、spill 清理、旧第三方缓存清理、项目删除、OCR、全文搜索或跨 Agent 迁移。
- 不静默安装更新，不接受任意更新来源，不发布 npm，不替换包运行器，也不承诺启用无需重启。安装仍交由当前 profile 的 DSH 原生插件管理器。
- 打开管理列表或预览不修改原生会话存储。
- 存储查看由用户手动开始且只读，不识别 AI 产物，不删除宿主或工作区文件。
