# 架构

简体中文 · [English](architecture.md)

插件支持 macOS 和 Windows 上的 DSH Desktop `0.2.1-rc.3`、`0.2.1-rc.5`、`0.2.2-rc.3` 和 `0.2.2-rc.5`，使用 JSONL 持久化。React 实例、原生控件、会话存储、工作区登记及活动／写锁服务均来自宿主。

## 模块

| 模块 | 职责 |
| --- | --- |
| `client` | 原生入口、选择、预览、确认及结果 |
| `service` | 会话组校验、串行转换、请求与恢复 |
| `dsh-adapter` | 宿主准入、关系、活动、写锁及原生登记 |
| `storage` | 回收站清单、操作日志、移动、恢复及永久清除 |
| `host-diagnostics` | 共享只读探测契约、检查名称与拒绝原因码 |
| `purge-history` | 有数量上限的永久删除完成记录 |
| `storage-inspector` / `storage-usage` | 来源解析和有上限的元数据扫描 |
| `update-source` / `update-service` / `update-host` | GitHub 校验、更新状态和原生 profile 安装 |

对 DSH 内部结构的访问集中在适配层。适配新宿主版本时，在这里修改，并同步更新验证这些行为的原生集成测试。

## API 与客户端状态

请求通过所有者鉴权的 `/api/dsh-archive-delete` 路由发送，接收的 JSON 流上限为 64 KiB。

| 动作 | 输入 | 结果 |
| --- | --- | --- |
| `list` | — | 支持状态、归档、回收站、最近结果、诊断及工作区选项 |
| `preview` | 动作和目标 ID | 组成员、大小、处理状态及到期时间 |
| `execute` | 预览 ID、请求 ID | 逐项结果及计数 |
| `cancelPending` | 会话 ID、请求 ID | 取消结果 |
| `storage` | 可选工作区 ID | 存储观察结果 |
| `updates` | 强制检查标记 | 发行及安装状态 |
| `installUpdate` | 候选 ID、请求 ID | 安装状态 |

文件路径和发行资产由服务端解析。客户端校验响应，并用请求代次区分新响应和较晚返回的旧响应；变更结果不明确时，通过同一请求 ID 重新核对。切换页签、分页或排序会清空选择，维护状态会作废尚未返回的预览。确认到期时间，以及可处理、尝试闲置释放和受保护的目标数，都来自当前预览。

归档变更的错误响应可携带可选布尔值 `error.uncertain`：

| 值 | 含义 |
| --- | --- |
| `true` | 意图可能已经发布或开始处理，需重试原请求 ID。 |
| `false` | 经过校验的查询确认，到期预览的请求没有回执或关联操作，可以重新核对新预览。 |
| 省略 | 本次错误不说明上一次尝试的结果。 |

服务在可能完成持久化准入后，将异常标为结果未确认。重试期间遇到临时拒绝，仍保留此前的未确认状态。连接旧版服务时，`operation-failed` 变更错误按结果未确认处理。读取错误和已经记录的逐项结果保持原有行为。

## 数据与转换

插件先取得存储写锁，再初始化数据目录。状态位于 `<DSH_HOME>/archive-delete/`：

| 路径 | 内容 |
| --- | --- |
| `trash/<entry>/` | 清单及按成员编号的日志目录 |
| `staging/<entry>/` | 移动中的会话组 |
| `operations/` | 持久转换阶段和恢复数据 |
| `receipts/` | 请求进度与幂等结果 |
| `purge-history/history.json` | 近 30 天内最多 200 条删除完成记录 |
| `updates/` | 按 profile 隔离的检查／安装日志 |
| `updates/packages/` | profile 依赖引用的已校验安装包 |

会话组包含母会话及其明确所属的专属子代理。fork 也带有母会话指针，因此适配层结合宿主的关系元数据区分两者。每次列出会话时建立一次关系索引。身份数据损坏会产生诊断，并保护已知的关联组；祖先无法定位时，阻止归档移动。

操作串行执行，重叠的刷新请求共用一次列表任务。服务先将预览标为已使用，再记录请求意图；意图落盘后才修改文件，每项结果落盘后才移除对应的已完成操作日志。使用原请求 ID 可以恢复已记录的意图和结果。

移动在同卷内进行，保留原始日志字节；文件转换完成后，适配层更新工作区和投影记录。恢复后，会话回到原工作区并保持已归档；原工作区登记缺失时归入未分组。确认永久清除后，移除所选回收站日志及恢复元数据。

日志移入暂存位置前，先同步暂存条目的父目录。永久清除依次同步成员文件删除、成员目录移除和清单移除，再同步回收站父目录与终态日志。POSIX 使用目录 fsync。Windows 支持进程中断后的恢复，整机断电后的持久性不作保证。按路径删除时，在移除前再次核对所属目录身份。

完成回执保留标识和结果，移除标题。最近结果缓存十条完成记录，每次读取都重新校验内容。排序索引一分钟到期，下一次读取会重建索引，即使目录身份未变，也能反映原地编辑后的排序。历史越多，初次清点和启动恢复耗时越长。启动时也会清理临时文件。

## 原生生命周期与写锁

手动确认移动后，插件可通过原生 AgentLoop 生命周期释放 DSH 持有的完全闲置会话组。适配层先检查归属、排队输入、维护、活动任务和子代理；释放完成后，服务再次检查成员和内容，取得正常写锁后再移动。待处理请求在启动时尝试一次，手动重新核对则会发起一次新的即时释放尝试。

比较会话头时，将宿主省略的 `delegationDepth` 视为磁盘默认值 `0`，其他值和会话身份仍按记录复查。

即时释放不可用时，适配层记录固定原因码和宿主版本。同一原因在一次完整释放成功前只记一次，之后再次出现时重新记录。所有者匹配失败的诊断包含 fiber 数、effect 数及生命周期标签前缀命中数。活动任务通过正常的逐项结果反馈。

管理列表会运行本机只读探测，复用释放流程中的运行时和所有者检查。各项显示通过、失败或尚未验证；空运行时的会话相关检查保持未验证，探测异常也返回未验证状态。探测仅读取结构，不刷新或关闭会话、不调用活动钩子、不修改文件。实际操作仍要求宿主版本受支持，并重新核对所选会话组的活动和身份。

macOS 使用宿主的 flock 句柄。Windows 使用宿主 JSONL 信号量名称，同时保留原路径及迁移后路径。规范本地路径使锁身份保持一致。插件在整个进程生命周期内持有存储写锁，以协调恢复和文件操作。

## 永久删除历史

永久删除历史与请求回执、恢复数据分开保存。正常执行或恢复确认清除已持久化完成后，会在移除操作日志前尝试原子更新私有历史文件。每条记录包含回收站／会话 ID、标题哈希、原始日志大小、成员数、首次确认完成时间及可选请求 ID，不保存明文标题、路径或会话内容。重放保留首次记录。持有存储写锁的实例清理过期记录，保留近 30 天内最多 200 条。归档操作不可用时，接口仍可只读展示最近的历史。历史写入失败只记录固定诊断，不改变删除结果，因此写入失败或进程中断可能造成记录缺失。恢复时确认完成的时间可能晚于实际文件移除。

## 存储观察

适配层解析 DSH 配置的存储位置和已登记工作区。DSH 扫描排除项目目录，以及已单独归类的子目录。工作区扫描结束后，检查器复查所选工作区的登记和路径，并比较排除集合。配置路径使用不同的上级目录别名时，按实际路径判断包含关系，并核对项目路径是否位于宿主存储内。

搜索索引分类统计已配置的 SQLite 数据库及其现存的 `-wal`、`-shm` 和 `-journal` 文件，也覆盖 DSH 主目录以外的位置。扫描只读取这些指定文件，不遍历其父目录。

扫描器在三项限制内读取元数据：50,000 个条目、32 层深度，inspector 预算为 5 秒。它在批次间让出执行，接受取消请求，并记录跳过、变化或无法访问的条目。结果包含观察时间，以及扫描完整或部分完成的状态。

主合计将相同的规范路径和已核实文件身份各计一次。分类之间可能重叠，目录合计则按文件路径计数。目录名和扩展名决定文件类型：依赖、构建目录、版本控制数据、日志、媒体、压缩包、代码／配置、文档及其他文件。类型小计在各分类内部去重，大文件行也会显示对应类型。

存储界面先显示紧凑的分类摘要，展开后可查看文件类型、大文件和目录。重新扫描同一范围时，保留上次结果和时间，直到新结果返回；切换范围时清空。

接口路径以 `/` 分隔；POSIX 文件名中的冒号和反斜杠在展示和分类时保留字面含义。这些路径仅用于展示，归档操作仍接收 ID。

## GitHub 更新

更新器从 `QwQBiG/dsh-archive-delete` 读取更高版本的稳定发行版，最多检查 20 条发行及五个新版候选。候选必须声明精确的 DSH 版本和平台。发行检查结果缓存 24 小时，手动检查至少间隔一分钟；失败后至少等待一小时，并遵守 GitHub 更长的退避时间。

安装前，服务端固定发行和资产的身份、版本、大小及 SHA-256。来源操作共用 15 秒网络预算，安装前校验的总预算为 30 秒。包校验器限制压缩、展开后的大小及 tar 条目，检查路径和包清单，并要求预编译文件。SHA-256 用于核对字节是否与通过 TLS／GitHub 从仓库取得的安装包一致。

已校验安装包保留在 `updates/packages/`，由 DSH 管理器替换当前 profile 中的同一 bundle。检查和安装日志按规范 profile 目录的哈希隔离。替换前先完成归档队列中的工作，安装任务在队列之外执行，让插件能够完成自身卸载。

插件卸载时取消发行检查和安装前校验。安装一旦交给原生管理器，后续生命周期由管理器控制。重新核对同一请求时，读取原生安装状态，已记录的安装不重复执行。检查间隔从 3 秒退避到 15 秒、60 秒；正在运行和已安装的版本决定更新已生效还是需要重启。

安装包的 `engines.dsh` 使用有数量上限的精确版本列表。默认更新元数据对应 `0.2.1-rc.3`，其他受支持版本各有一个元数据文件，均指向同一个安装包和校验值。读取 ASAR 内的宿主清单时，专用读取器也会校验所属归档。

每个已准入请求还保留原子写入的 `<profile-hash>.<request-id>.request.json` 回执，绑定候选版本及版本号。先写回执，再发布最近状态文件，最后调用管理器；结果也先写入独立回执。最近状态副本更新中断时，启动恢复使用独立回执，并迁移旧版仅保存最近一次安装的记录。重放旧回执不改变最近状态。回执持续保留，旧请求 ID 不会重新进入安装；查询只读取对应文件。

## 安装包与诊断

Release `.tgz` 包含包清单中 `files` 白名单选中的文件，以及其中已编译的 `lib/` 文件。产物脚本使用运行时包校验器；检查脚本先核对 `.tgz.sha256`、`.update.json` 和安装包字节是否一致，再运行发行检查与下载样本。

启动完成恢复和 API 注册后，会记录插件版本、宿主和回收站路径。安装包中的 Doctor 可离线检查 profile 登记、包文件和访问权限。使用方式见 [安装命令](installation.zh-CN.md)、[状态恢复](operations.zh-CN.md) 和 [验证记录](acceptance.zh-CN.md)。

Doctor 的 `--codes` 模式按所选语言列出原因码，无需检查 profile。在源码仓库中运行 `scripts/probe-host.mts`，会在自有临时目录启动官方服务并生成 JSON 报告，省略用户路径和会话数据。它不打开用户 profile，也不创建会话，因此所有者检查保持未验证。CI 为每个宿主／平台组合保留报告。未声明版本即使结构检查通过，数据操作也保持禁用。
