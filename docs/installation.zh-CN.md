# 安装使用指南

简体中文 · [English](installation.md)

## 支持环境

- 官方 DSH macOS Desktop `0.2.1-rc.3`。
- 官方 JSONL 会话存储，插件回收站与其位于同一磁盘卷。
- 不修改 DSH 应用包、现有 `dsh-purge` 或项目工作目录。

插件会检查运行能力。出现不支持提示时，不应绕过版本或路径检查。

## 从 GitHub 安装

`v0.1.0` 发布后，在桌面端打开 **插件 → 添加插件**，输入：

```text
github:QwQBiG/dsh-archive-delete#v0.1.0
```

安装并启用，仅在 DSH 提示宿主半需要重启时重启。使用桌面端实际 profile 的插件管理器，不要装到无关的命令行 `web` profile。

已经显式安装 DSH 命令行工具的用户，可使用等价命令：

```sh
dsh plugin --profile desktop add github:QwQBiG/dsh-archive-delete#v0.1.0
```

安装包含宿主与浏览器产物，GitHub 安装无需运行依赖的构建／prepare 脚本。

## 开发用本地安装包

使用独立 DSH home/profile，且只放合成会话。构建并打包后，将生成的 `.tgz` 绝对路径交给该隔离 profile 的插件管理器：

```sh
pnpm install --frozen-lockfile
pnpm verify
pnpm pack
```

安装打包产物可避免把开发依赖中的 DSH 或 React 当作第二套宿主运行时。不要使用主 profile 做集成测试材料。

## 归档与移入

先使用 DSH 原有的归档操作。插件不重复实现归档流程，也不会默默停止正在运行的工作。

在已归档会话的原生菜单选择 **移入回收站**。多条操作时，打开 **插件 → Archive Delete → 管理归档与回收站**，在 **已归档** 选中目标，检查影响后确认。

选择仅属于当前页签，切换页签会清空。批量结果分别显示成功、待处理、跳过与失败；解决失败原因后只重试相应目标。

## 待重启处理

闲置的已归档会话仍可能被当前宿主保留。确认请求可以保存为 **待移入回收站**，原日志保持原位，会话仍留在归档列表；改变主意时可在此取消。

下次插件启动完成恢复检查后，只尝试一次请求。目标重新活动、内容变化、取消归档或不安全时，不会使用旧确认继续移动。待处理不表示已经回收磁盘空间。

## 恢复或清除

**回收站** 显示实际已移动的会话组。**恢复** 会返回原工作区的已归档状态；原工作区不存在时，恢复为未分组的已归档会话。源路径冲突时报告错误，不覆盖数据。

**永久删除** 需要新的预览和确认，仅清除选中的回收站日志和恢复元数据，不删除共享附件、spill、项目文件、其他插件缓存或远端副本。回收站不会自动过期。

## 卸载或更新

通过 DSH 插件管理器卸载／更新，并遵循它的重启提示。卸载不清除回收站或待处理操作记录，重新安装受支持版本后可以检查保留的记录。备份时应把待处理／恢复文件和回收站一起保留；手动搬动运行中内部文件不是受支持的恢复方式。

操作失败时保留状态，针对同一目标重试。报告问题时提供宿主／插件版本及脱敏复现。预期状态见 [操作恢复](operations.zh-CN.md)。
